# Working in this repository

Dörtyol is a 3D driving game for phones: a static site in `game/`, wrapped for
Google Play with Capacitor, whose every 3D model is generated by Python
scripts in `blender/` rather than modelled by hand or downloaded.

The standard this repository is held to is
[docs/ENGINEERING-STANDARDS.md](docs/ENGINEERING-STANDARDS.md). Read it before
your first change here. The short version: finish the thing, leave no dangling
threads, fix causes rather than working around them, and never hand-edit a
generated file.

## Commands

```bash
npm install
npm run check     # the standards gate: ~1 s, no browser, no dependencies
npm test          # the gate, then four browser suites in headless Chromium
npm run serve     # play it at http://localhost:8000
npm run sw        # regenerate the offline cache -- after ANY change under game/
npm run assets    # regenerate every .glb + manifest.json (needs `pip install bpy`)
npm run store     # regenerate icons, the logo and the store art
```

`npm run check` is the first thing to run and the last thing to run. It is
also the first suite `npm test` runs.

## Where things are

```
game/js/         the game. main.js is the entry point; config.js holds every
                 tuning number; i18n.js holds every player-facing string
game/index.html  the app shell: every screen, every element id
game/sw.js       GENERATED by tools/make_sw.py -- never edit it
blender/lib/     the model generators; kit.py is the shared low-poly toolbox
tests/           browser suites + the standards gate; harness.mjs is the
                 shared browser setup every suite uses
tools/check.mjs  the standards gate
docs/RELEASE.md  what is still needed to ship on Play, and what is unverified
```

`game/assets/models/manifest.json` is generated by `blender/build_all.py` and
carries each model's real triangle count and bounding box. The game reads its
collision sizes, lane positions and city grid from it, so gameplay always uses
the numbers of the geometry that actually shipped. Do not duplicate those
numbers in code.

## The rules that bite

- **Both languages or it does not ship.** Every player-facing string lives in
  `game/js/i18n.js`, in the `tr` and `en` tables. The gate fails on a key that
  exists in one and not the other, on placeholders that differ between them,
  on a key nothing uses, and on a key the code asks for that nothing defines.
- **Regenerate what is generated.** Any change under `game/` makes `game/sw.js`
  stale; `npm run sw` fixes it and the gate fails until you do. A stale
  service worker means returning players keep the old build forever.
- **No TODOs.** Do it now, or decide out loud not to and remove the half of it
  that exists. The gate fails on the marker itself.
- **Tests are the spec.** Anything the README claims about behaviour should
  have a `check(...)` line behind it. New suites are found automatically: drop
  a `*.test.mjs` into `tests/`; browser suites get their page from
  `tests/harness.mjs` rather than launching Chromium themselves.
- **A new check needs a planted mistake.** `tests/gate.test.mjs` proves every
  rule in the gate actually fires, by planting it in a throwaway copy of the
  tree. Add a check, add its mistake in the same commit.
- **100 columns, two spaces, single quotes, no tabs**, and a header comment on
  every module saying what it is for.
- **Turkish for players, English for developers.** The README is written for
  players and is in Turkish; code, comments, commit messages and `docs/` are
  in English.

## Before you say it is done

Run `npm test` — all of it, not the suite you were working on — and work the
checklist in
[docs/ENGINEERING-STANDARDS.md](docs/ENGINEERING-STANDARDS.md#done-means).
Commit messages here are prose: what changed, why that way, what it cost, and
a closing line with the check count.

## What is not verified

The `.aab` has never been built and the game has never run on a real phone:
this repository was developed in an environment that cannot reach
`dl.google.com`, so there is no Android SDK, and it renders with software
OpenGL at about four frames a second. [docs/RELEASE.md](docs/RELEASE.md) is
the honest list of what remains. Do not describe the game as shipped, and do
not quietly assume a performance number that only real hardware can give.
